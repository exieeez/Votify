## Офлайн демо-каталог
Если YouTube/SoundCloud недоступны (нет сети, файрвол, песочница), поиск и рекомендации автоматически возвращают локальный демо-каталог из 8 треков: аудио синтезируется на лету в памяти (WAV 22 кГц), обложки — генерируемые SVG. Треки играются, добавляются в плейлисты и закрывают все экраны контентом. Отключается переменной окружения `VOTIFY_DEMO=0`. Файлов на диске не создаётся.

## Как устроен движок

**[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)** — как работает Android-приложение: два режима
источника музыки (встроенный NewPipeExtractor и свой сервер), воспроизведение через
Media3/ExoPlayer и `votify://stream/<id>`, офлайн-загрузки, Room/DataStore, UI-слой и сборка.

## Аккаунт, юзернеймы и друзья

Полная спецификация — в **[`docs/ACCOUNT.md`](docs/ACCOUNT.md)**: авторизация (Firebase Identity
Toolkit REST), коллекции Firestore `usernames` / `profiles` / `friendships`, правила доступа и
список того, что считается заглушкой. Профили и друзья работают только у Firebase-аккаунтов;
экраны Android — `android/app/src/main/java/app/votify/mobile/ui/account/`.

## Ветки репозитория

* **`pc`** — версия для компьютера (Electron + сервер + веб-интерфейс);
* **`mobile`** — версия для телефона (Android-приложение, APK собирается из неё);
* временные ветки `arena/*` живут только на время сессий разработки.

Как перестроить ветки (две основные вместо временных) и как залить на GitHub актуальную
папку с компьютера — **[docs/GIT-BRANCHES.md](docs/GIT-BRANCHES.md)**, скрипты:
`scripts/git-split-branches.sh` и `scripts/push-folder.ps1`.

## Votify на телефоне (ярлык в браузере)

Пока приложение запущено на компьютере, тот же интерфейс открывается с телефона — ярлыком
на домашнем экране, без установки APK и без App Store. Если компьютер не нужен —
см. следующий раздел про развёртывание на хостинге:

1. Настройки → **Основные → «Votify на телефоне»** — там адрес ПК в Wi-Fi сети
   (например `http://192.168.1.10:17217`) и кнопка «Скопировать».
2. Телефон в той же Wi-Fi сети открывает этот адрес в браузере.
3. **iPhone:** «Поделиться» → «На экран „Домой“». **Android:** меню «⋮» → «Установить
   приложение» (или «Добавить на главный экран»).

Интерфейс сам перестраивается под телефон (нижняя навигация, компактный плеер, отступы под
вырез и «домашнюю полоску»): `src/styles.css` → `MOBILE RESPONSIVE` + блок про
`env(safe-area-inset-*)`. Ярлык задаётся файлами `src/manifest.webmanifest`,
`src/icons/*` и apple-мета в `src/index.html` (иконки пересобираются скриптом
`scripts/generate-web-icons.sh`).

Что важно знать:

- музыка идёт **с компьютера** (yt-dlp на ПК), поэтому пока он выключен — телефон ничего не
  сыграет; телефон и ПК должны быть в одной сети;
- адрес — обычный `http://`, а не `https://`: ярлык и воспроизведение работают, но
  service worker/офлайн-кэш браузер в таком режиме не разрешает (это ограничение iOS/Chrome,
  а не Votify);
- на iOS воспроизведение продолжается при свёрнутом браузере, но система может остановить
  звук при блокировке экрана — это политика Safari;
- если адрес не открывается — разрешите Votify доступ в брандмауэре Windows (входящие
  подключения, порт 17217).

## Отдельное приложение на iPhone (без компьютера)

На iPhone нельзя поставить APK, но можно сделать **полноценное приложение-ярлык**: Votify
работает как сайт, который добавлен на экран «Домой», — со своей иконкой, во весь экран,
из любой сети и **без вашего компьютера**. Для этого бекенд Votify должен жить на хостинге.

### Вариант 1. Render (проще всего, свой сервер не нужен)

Пошаговая инструкция для новичка — **[docs/DEPLOY.md](docs/DEPLOY.md)** (аккаунт, деплой,
пароль, ярлык на iPhone, обновления и что делать, если что-то не так). Коротко:

1. [render.com](https://render.com) → вход через GitHub → **New → Blueprint** → выбрать
   репозиторий Votify (Render прочитает `render.yaml` и соберёт Dockerfile сам).
2. Задать `VOTIFY_BASIC_AUTH` = `логин:пароль` — иначе адресом смогут пользоваться посторонние.
3. Получить адрес вида `https://votify-xxxx.onrender.com`.
4. На iPhone открыть его в **Safari** → **«Поделиться» → «На экран „Домой“»**.
   Android: Chrome → «⋮» → «Установить приложение».

Бесплатный план засыпает после ~15 минут простоя (первый заход после паузы — до минуты) и
не имеет диска: аккаунты и синхронизацию лучше держать в Firebase (`VOTIFY_FIREBASE_CONFIG`),
тогда передеплой ничего не теряет. Чтобы сервис не засыпал — бесплатный пинг `/api/health`
раз в 10 минут (детали в docs/DEPLOY.md). Постоянно работающий вариант — небольшой
VPS/NAS/Raspberry Pi, тоже без своего сервера можно обойтись облачным Docker-хостингом
(Koyeb, Fly.io, Cloud Run — см. ту же инструкцию).

### Вариант 2. Свой сервер (VPS, NAS, Raspberry Pi) — Docker

```bash
# из готового образа (собирается CI-воркфлоу docker.yml)
docker run -d --name votify -p 17217:17217 \
  -e VOTIFY_BASIC_AUTH=логин:пароль \
  -v votify-data:/root/.config/Votify \
  ghcr.io/exieeez/votify:latest

# или из исходников
docker compose up -d          # см. docker-compose.yml, пароль — в .env
```

По желанию добавьте HTTPS (Caddy/nginx/Tailscale) — тогда адрес будет `https://…`, и браузер
предложит установить приложение (иконка, полноэкранный режим; на iOS ярлык работает и без
HTTPS). Офлайн-оболочка (service worker) пока не подключена — интерфейс грузится с сервера.

### Что это даёт и чего не даёт

- Иконка на экране «Домой», запуск во весь экран, без адресной строки — как обычное приложение.
- Работает из любой сети, компьютер может быть выключен: поиск и звук считает сервер.
- Звук продолжает играть при свёрнутом браузере; на iOS система может останавливать
  воспроизведение при блокировке экрана — это политика Safari, обойти её без приложения
  из App Store нельзя.
- Android-приложение при этом может указать этот же адрес как «Свой сервер»
  (Настройки → Прокси/сервер) — тогда телефон и ярлык используют одну библиотеку.

## Сборка и запуск

### Требования
- Node.js (v20+)
- npm

> 📱 **Android-версия** Votify живёт в отдельной ветке [`android`](https://github.com/exieeez/Votify/tree/android) — каталог `android/` (Kotlin, Room, оффлайн-загрузки). Эта ветка (`main`) содержит только ПК-приложение.

### Установка зависимостей
```bash
npm install
```

### Запуск в режиме разработки
```bash
npm start
```

### Discord Rich Presence

Application ID Votify уже встроен в приложение, поэтому дополнительная настройка переменных окружения не требуется. Запустите Discord Desktop, затем Votify:

```bash
npm install
npm start
```

Votify показывает в Discord название трека, исполнителя, обложку и таймлайн воспроизведения. На паузе таймлайн скрывается, чтобы он не продолжал идти; после возобновления или перемотки он автоматически синхронизируется.

При необходимости встроенный Application ID можно переопределить:

```bash
VOTIFY_DISCORD_CLIENT_ID=другой_application_id npm start
```

Для локальных треков без публичной обложки можно дополнительно указать ключ изображения, загруженного в Rich Presence Art Assets:

```bash
VOTIFY_DISCORD_LARGE_IMAGE_KEY=votify npm start
```


#### Мастерская тем

Встроенная мастерская хранит публичные темы в `workshopThemes/{themeId}`. Просматривать, искать и устанавливать темы можно без аккаунта; публиковать и удалять собственные темы могут только постоянные Email/Google-аккаунты. Гостевые аккаунты перед публикацией нужно привязать.

После обновления приложения обязательно повторно опубликуйте `firestore.rules` в Firebase Console. Правила разрешают только безопасный набор цветов и параметров, а также HTTPS-ссылку на фон длиной до 2048 символов; запрещают изменение публикаций и позволяют удаление только владельцу. Локальные изображения, HTTP-ссылки и произвольный CSS в мастерскую не загружаются.

Правила также можно опубликовать через Firebase CLI (при первом использовании откроется вход Google):

```bash
npx firebase-tools@15.26.0 login
npm run deploy:firestore-rules
```

### Сборка релизных дистрибутивов (Linux AppImage & deb)

```bash
# Сборка AppImage & deb (Linux)
npx electron-builder --linux AppImage deb

# Сборка .exe (Windows)
npm run build:win
```

Собраные файлы будут находиться в папке `dist/`.
