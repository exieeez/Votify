# Ветки репозитория: две основные вместо кучи временных

## Что есть сейчас

| Ветка | Что это | Состояние |
|---|---|---|
| `main` | старые ручные выгрузки ПК-папки через сайт GitHub («Add files via upload»), без `android/` | ветка по умолчанию, устарела |
| `android` | старая версия для телефона: ПК-код + папка `android/` (Kotlin/Compose) | устарела |
| `my-pc` | **версия 1.0 с компьютера** — то, что залил владелец | влита в ветку сессии |
| `arena/01a0ae5a-votify` | версия 1.0 + перенесённые доработки: выбор иконки приложения, ярлык на телефон (PWA), адрес в Wi-Fi, `/api/health`, скрипты веток | **самый новый код** |
| `arena/01a08af6…`, `01a08c8e…`, `01a09b4c…`, `01a089d8…`, `01a08746…` | временные ветки прошлых сессий Arena | устарели |

За основу новых веток берётся **версия 1.0 с ПК** — она полнее, чем `main` (там есть `android/`,
соцсеть, чарты, новая оболочка), и в неё уже добавлены свежие доработки.

## Что предлагается

Оставить **две** долгоживущие ветки:

| Ветка | Назначение | Из чего собирается CI |
|---|---|---|
| `pc` | компьютер: Electron + сервер + веб-интерфейс | Docker-образ, релизы приложения |
| `mobile` | телефон: Android-приложение | APK (Android CI, Release APK) |

Обе ветки содержат **весь проект целиком** — один и тот же код с двумя линиями релизов.
Держать в `pc` только ПК-файлы, а в `mobile` только Android — можно, но тогда любую правку
общих файлов (`src/`, `server.js`, `README.md`) придётся делать дважды и ветки быстро
разъедутся. Разделение по релизам удобнее и не ломает сборки.

## Как перестроить (один скрипт)

В клоне репозитория (Git Bash на Windows, терминал macOS/Linux):

```bash
cd путь/к/Votify
git pull                                       # подтянуть свежий код
# если ветки arena/01a0ae5a-votify ещё нет локально:
git fetch origin && git checkout arena/01a0ae5a-votify
bash scripts/git-split-branches.sh --dry-run      # посмотреть план, ничего не меняя
bash scripts/git-split-branches.sh                # сделать (скрипт спрашивает подтверждение)
```

Скрипт по шагам:

1. создаёт `pc` из самого свежего кода (версия 1.0 + доработки) — весь проект целиком;
2. создаёт `mobile` из того же свежего кода;
3. предлагает сделать `pc` веткой по умолчанию (через `gh`, если установлен);
4. предлагает удалить старые ветки: `android`, все `arena/*` и `main`;
5. ветку `arena/01a0ae5a-votify` спрашивает отдельно — **она привязана к текущей сессии Arena**,
   удалять её стоит последней (после того как убедитесь, что всё влито).

Если GitHub CLI (`gh`) не установлен — ветка по умолчанию меняется в веб-интерфейсе:
**Settings → Branches → Default branch → `pc`**.

## Как залить на GitHub актуальную папку с ПК

### Вариант A. Скриптом (Windows, PowerShell)

```powershell
cd C:\путь\к\Votify
powershell -ExecutionPolicy Bypass -File scripts\push-folder.ps1 -Folder C:\путь\к\Votify
```

По умолчанию папка уезжает в **новую** ветку `pc-upload` — ничего не ломается, потом можно
открыть Pull Request и влить в `pc`.

Залить прямо в ветку ПК:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\push-folder.ps1 -Folder C:\путь\к\Votify -Branch pc
```

Скрипт сам: проверит git, инициализирует репозиторий (если папка ещё не под git),
подключит `origin`, допишет `.gitignore` (`node_modules/`, `dist/`, `release/`, `.env`…),
прикрепится к последнему коммиту нужной ветки **не трогая файлы на диске**, покажет, что
попадёт в коммит, предупредит про файлы больше 90 МБ и отправит.

### Вариант B. Вручную (любая система)

```bash
cd путь/к/Votify
git init -b pc                      # если папка ещё не под git (иначе: git checkout -B pc)
git remote add origin https://github.com/exieeez/Votify.git   # или: git remote set-url origin …
git fetch origin --prune
git reset --soft origin/pc           # «приклеиться» к ветке, файлы на диске не меняются
git add -A
git status                           # глазами проверить: node_modules и .env быть не должно
git commit -m "Актуальная версия с ПК"
git push origin pc
```

Если GitHub отвечает `! [rejected] ... non-fast-forward` — значит на GitHub есть коммиты,
которых нет в вашей папке. Два пути:

* **правильный**: `git push origin pc:pc-upload` → открыть Pull Request → посмотреть разницу
  и влить;
* **быстрый** (папка точно новее, изменения на GitHub не нужны):
  `git push --force-with-lease origin pc`.

### Чего в папке быть не должно

`node_modules/`, `dist/`, `release/`, `.env`, `firebase-config.json`, `*.log` — всё это уже
перечислено в `.gitignore`; если папка новая и `.gitignore` в ней нет, скрипт его создаст.
Секреты (токены, пароли, приватные ключи Firebase) в публичный репозиторий не заливайте —
они попадают в историю git навсегда.

### Вход в GitHub

Git for Windows при первом `push` откроет окно входа (Git Credential Manager) — просто
войдите в браузере. Альтернатива: Personal Access Token (GitHub → Settings → Developer
settings → Tokens (classic), галочка `repo`) в роли пароля. **Никому не пересылайте токен**,
его не нужно вставлять в чаты и тикеты.

## Как это скажется на сборках

* **APK для телефона** — из ветки `mobile` (воркфлоу `Android CI` и `Release APK`;
  в них добавлены новые имена веток, так что переименование их не сломает).
* **Docker-образ** (веб-версия/ярлык на iPhone) — из `pc` и `mobile` (воркфлоу `Docker image`).
* **Релизы приложения для ПК** — по тегам `v*`, от ветки не зависят.
* Пока ветки `main`/`android` не удалены, старые воркфлоу продолжают на них реагировать —
  поэтому удаление безопасно делать после того, как `pc` и `mobile` запушены.
